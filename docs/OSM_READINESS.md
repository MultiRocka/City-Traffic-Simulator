# OSM readiness

Honest status for OpenStreetMap Overpass JSON import into Easy Rider. **This is not OSM plug-and-play with zero work.** Stages 2–5 provide an offline importer path into the existing `MapDescription` → `City` model; several real-world OSM features remain unsupported or approximated.

Related: [OSM_IMPORT.md](OSM_IMPORT.md), [CODE_TOUR.md](CODE_TOUR.md), [MAP_MODEL.md](MAP_MODEL.md), [PRIORITY.md](PRIORITY.md), [PEDESTRIANS.md](PEDESTRIANS.md), [LANE_BLOCKS.md](LANE_BLOCKS.md), [RUN.md](../RUN.md).

## How map data enters `City`

```
Overpass JSON (offline)          synthetic Demo
        │                              │
        ▼                              ▼
 OsmJsonParser → OsmDocument    Scenario::buildDemoMapDescription()
        │
        ▼
 OsmToMapDescription → MapDescription + ImportReport
        │
        ▼
 CityBuilder::build(description, city, error)
        │  validates ids, lengths, lanes, polylines, crossings, connections
        │  applies PriorityMode / priorityRoadIds / turn disallows
        ▼
      City
        │
        ▼
 OsmScenarioBuilder attachments (Simulation):
   VehicleGenerator routes, generated PhaseController / TrafficLight,
   PedestrianCrossing instances
        │
        ▼
 SimulationSession::loadOsmFromFile / loadDemoScenario  →  Win32 GUI
```

**Default GUI / console scenario:** `Scenario::setupDemoCity` → `SimulationSession::loadDemoScenario`.  
**OSM GUI path:** **Load OSM…** → `SimulationSession::loadOsmFromFile` (transactional).  
**Regression grid:** `loadIntersectionTestScenario` remains available (non-GUI / tests).

## Tick flow (learning)

Fixed physics step: `simulationDt = 0.1 s` (10 Hz). Short bilingual tour of key classes + one tick: [CODE_TOUR.md](CODE_TOUR.md).

Core rules never branch on magic demo `roadId` / `laneId`. Scenarios and tests discover topology via `City` queries. Scenario swaps stop the session first (no mid-tick replace).

## Directions vs lanes

| Concept | Model |
|---------|--------|
| One directed edge | one `RoadSegment` (`from` → `to`) |
| Two-way street | **two** directed `RoadSegment`s (opposite endpoints) |
| `laneCount` | lanes for **that direction only** (≥ 1) |

Never encode opposite travel as extra lanes on the same segment. Importers must split OSM bidirectional ways into two directed edges (or one if the way is truly oneway).

---

## Geometry → length / render

| Field | Role |
|-------|------|
| `MapRoadDesc::length` | **Authoritative** for motion, crossings, blocks (meters) |
| `intermediatePoints` | Optional polyline between endpoints for **render** / layout |
| Validation | If intermediates present, polyline length (from → points → to) must match `length` within `CityBuilder::polylineLengthTolerance` (default 1.0 m) |

`CityLayout` / `MapView` fit world bounds into the viewport. Vehicles move in longitudinal meters, not along raw OSM node chains unless the importer sets `length` and intermediates consistently.

## Limits, crossings, priority

| Input | Where set | Enforced? |
|-------|-----------|-----------|
| `speedLimit` (m/s) | `MapRoadDesc` | **Yes** — cruise capped by road limit |
| `laneCount` | `MapRoadDesc` (−1 → default 1) | **Yes** — spawn / LC / blocks |
| `MapCrossingDesc` | validated in builder; instances on `Simulation` | **Yes** when attached — pedestrians (attachment may be **capped**; see sim policy) |
| `PriorityMode` + `priorityRoadIds` | `MapIntersectionDesc` → `Intersection` | **Yes** — `IntersectionRules` |
| `MapConnectionDesc` `allowed=false` (via-node `no_*`/`only_*`) | turn ban on `City` | **Yes** — connectivity / PathFinder |
| via-way / conditional / `turn:lanes*` | `ImportReport.unsupported` | **WARN only** — not enforced |
| Car access hierarchy | omit way / `allowAutoDemand` | **Yes** for forbidden / destination auto-demand rules |

Signal **mode** can come from OSM (`traffic_signals`). Signal **timing** is generated by `OsmScenarioBuilder`, not read from OSM.  
`maxAttachedCrossings` / `maxGeneratedPhaseControllers` / `maxRouteHops` are **simulation policy caps** (defaults 32 / 24 / 12) — they do **not** truncate the imported map graph; see [OSM_IMPORT.md](OSM_IMPORT.md).

## Validation (`CityBuilder`)

Rejects (among others): duplicate / negative ids, missing intersections, `length ≤ 0`, `laneCount < 1` when set, crossing position outside `[0, length]`, connections that are not geometrically adjacent, polyline/length mismatch beyond tolerance.

On failure: `build` returns `false`, sets `error`, leaves `outCity` empty/failed. `loadOsmFile` / `loadOsmFromFile` roll that into a failed result without swapping the live city.

## Defaults vs source values

| Field | If unset / empty |
|-------|------------------|
| `laneCount == -1` | **1** |
| `sourceRef` empty | synthetic / local (not from external id) |
| `priorityMode` | `None` (runtime unsignalized → YieldToRight) |
| connections | all geometric turns allowed |
| polyline | empty → straight chord for layout |
| `speedLimit` (importer) | **50 km/h → m/s** when OSM maxspeed missing/unsupported |

Non-empty `sourceRef` is opaque provenance (e.g. `way/123`). Core does not parse OSM tags.

## Status summary

### (1) Works today (Stages 2–5)

- Overpass JSON parse → `OsmDocument`
- Tag → `MapDescription` + honest `ImportReport` (projection, oneway, lanes, maxspeed, crossings, signalized mode, stop/give_way)
- `OsmScenarioBuilder::loadOsmFile` transactional attach (generators, generated phases, crossings)
- `SimulationSession::loadOsmFromFile` / `loadDemoScenario` / reset preserving Demo vs OSM path
- Win32 GUI: Wczytaj OSM…, **Szukaj miejsca…** (limited Nominatim + Overpass), Miasto demo, import summary MessageBox, Start on imported map
- Offline fixtures + Warsaw sample 300 s smoke (when sample present)
- MapView auto-fits imported bounds
- `data/cache/` for geocode/Overpass reuse; fake-transport offline download tests

### (2) Integration boundary

- Stable plain-data structs (`MapDescription.h`) as the importer target
- Units documented (m, s, m/s)
- `sourceRef` hooks for provenance
- Failure keeps previous scenario; no mid-tick swap
- Download worker never mutates `Simulation`; UI marshals via `PostMessage`

### (3) Not done / approximate

- No `.osm` XML / PBF; **no full-OSM / whole-city** auto-download (area capped ~2 km radius rectangle)
- Basic via-node `no_*`/`only_*` restrictions + car access hierarchy — **enforced**; via-way / conditional / `turn:lanes*` — **WARN only**
- Signal timing — **generated sequential greens**, not OSM or coordinated plans
- Attachment / route caps may leave some crossings or signalized junctions without live ped/phase attachment
- No sidewalk graph, elevation, bridge/tunnel proximity joins, LH traffic switch
- No guarantee raw OSM geometry length equals driveable length without cleanup
- Visual GUI evaluation is manual
- Contact URL/email beyond User-Agent is a config placeholder (fill if provider policy requires)

**Do not claim:** full-OSM plug-and-play, whole-city download, complete restriction/access semantics, or real signal timing.  
**Do claim:** offline Overpass JSON → City path; basic via-node turn bans + documented car access hierarchy **enforced**; unsupported cases **WARN**; limited place download with explicit size/area caps.
